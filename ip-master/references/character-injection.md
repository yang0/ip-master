# 角色注入协议

1. 用 `character_router.py` 按中文名和不区分大小写的英文别名解析角色。传入
   `--project-dir` 时，同时检索该项目角色库；内置角色仍保持全局可用，项目角色
   只从项目目录解析素材和身份协议。
2. 用户未明确指定角色时，`create` / `prompt` 均不注入项目 IP，也不从上一张
   独立设计继承牙仔。注册表的历史 default_character 字段不触发注入。
3. 每个选中角色只读取自己的原始参考图和身份协议。原图按注册表顺序
   排在所有目标 Skill 的风格图、布局图之前，并给每张图稳定的
   `Image N: <name> identity reference only` 标签。
4. 角色原图只控制身份：体型、五官、服饰、配色和其他协议锚点。目标
   Skill 控制媒介、笔触、场景、版式和空间关系。
5. 多角色各自保持身份，不能合成混合角色；每个点名角色都要参与核心
   内容表达，不得退化成角落装饰。
6. 角色原图不是上游“真人脸部参考图”或风格图，不得改变为真人或用来
   覆盖目标 Skill 的媒介规则。
7. IP Master 不生图、不复制上游素材，也不在路由阶段安装依赖。

## 组合生成

- 指定 IP 是角色替换：牙仔接手小黑的核心物理动作，最终提示词删除小黑的
  外形要求、默认角色图和“小黑必须出现”条款。只有用户明确要求同框才保留两者。
- 明确手绘编号时，该风格接管媒介、笔触、配色和材质。先读取该编号并运行
  其模型能力解析器；不能仅写风格名称，又加入其他 Skill 的冲突画风限制。
- 小黑 2.0 使用 `ian-xiaohei-scenes` 提炼文章观点、物件和物理动作；当用户
  指定其“配图逻辑”并搭配手绘风格时，保留物件互动而将真实摄影改为所选手绘。
- 生成前整理为一份无冲突的提示词，明确内容方法、角色替换、风格来源。
  生成后逐项检查角色数量、核心动作、所选风格是否可辨识。只把编号写进
  提示词不代表风格已实现；失败时重写或重生成，不标为已完成。

`character_router.py --json "用绒宝和牙仔做知识漫画"` 可检查解析顺序；
`character_router.py --project-dir "E:\projects\品牌IP" --json "用项目角色做知识漫画"`
可检查项目角色；
路由器在目标尚未确定时返回空的 `referenced_image_paths`，避免提前注入。
